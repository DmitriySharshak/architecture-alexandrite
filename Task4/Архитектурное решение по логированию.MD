### Мотивация

Уважаемая команда!

Мы внедряем централизованное логирование.
Сейчас мы не знаем, что происходит с нашим продуктом, пока нам не пожалуется клиент. Разбор инцидента занимает часы, потому что логи разбросаны по разным серверам, и разработчики просят друг у друга доступы. Это не эффективно.

Централизованный сбор логов позволит нам:
Расследовать инциденты за минуты и обнаруживать проблемы раньше клиентов. 

### Предлагаемое решение
Внедрение логирования напрямую повлияет на следующие метрики:
| Метрика  | Текущее состояние | Целевое состояние |  Влияние логирования  |
| -------- | ------------------| ------------------| ----------------------|
|Удовлетворенность клиентов|Поступают жалобы|Повыщается лояльность| Скорость разбора проблем напрямую зависит на качество поддержки и удовлетворенность клиентов|
|Количество обращений на разработку|Все жалобы идут к разработчикам|Жалобы принимает специалист техподдержки|Снижение нагрузки на команду разработки, больше времени на выпуск новых фичей и хотфиксов |
|Среднее время устранения проблемы|Часы|10 минут |Сразу видим контекст ошибки|

В качестве стека для централизованного сбора и анализа логов предлагаю использовать Grafana Loki. 
Учитывая, что мы уже планируем Prometheus и Grafana для метрик, Loki является более предпочтительным, так как позволяет использовать единую панель управления (Grafana) для метрик, логов и трейсов.

Компоненты для внедрения и доработки:

1. Агенты сбора: установить на каждый сервис Fluent Bit для чтения логов из файлов и отправлять их в Loki.
2. Развернуть Grafana Loki как централизованный сервис. Loki будет хранить логи и индексировать их.
3. Для хранения логов использовать S3-совместимое хранилище 
4. Выполнить структурирование логов. Зафиксировать единый формат логов для Java и С# приложений

### Безопасность
1.Внедрить аутентификацию в Grafana 
2. Настроить RBAC в Grafana:
   Роль "Поддержка": Доступ только к поиску логов.
   Роль "Разработчик": Полный доступ к логам своего сервиса.
   Роль "Администратор": Полный доступ ко всем логам и настройкам.
3. Настроить маскирование чувствительных данных
4. Обеспечить шифрование трафика (TLS) 

Политика хранения:
Горячее хранение: 7 дней. 
Холодное хранение: 30-90 дней. Для расследований. 
Цифры по глубине хранения нужно будет скорректировать исходя из объема заказов в день и структуры логов, а также доступной нам системы хранения
